Публичный контракт не изменился — `from shared import AIEngine` работает как прежде, движок подгружается в момент обращения. Ни один вызывающий не пострадал: все 20 потребителей и так пишут `from shared.ai_engine import AIEngine`.

Проверено: обе сверки зелёные, `from shared import settings_store / bot_bus / assistant_memory` работают, неизвестный атрибут по-прежнему даёт ImportError.

### P1 — три роута отдавали клиенту внутренности ошибки

[api/admin/customers/route.ts](../apps/web/src/app/api/admin/customers/route.ts), [api/admin/learnings/route.ts](../apps/web/src/app/api/admin/learnings/route.ts) возвращали `error?.message` прямо в теле ответа. В проде это имена таблиц, полей и куски SQL из stack'а Prisma. Ровно от этого написан [lib/safeError.ts](../apps/web/src/lib/safeError.ts) — но эти роуты его не использовали. Переведены на `safeError(error)`.

### P1 — правка ресторана падала целиком при очистке поля

[api/admin/magazine/restaurants/route.ts](../apps/web/src/app/api/admin/magazine/restaurants/route.ts) собирал патч циклом по массиву строк в `data: any`:

```ts
for (const k of ['name', 'city', 'tier', ...]) {
  if (k in rest) data[k] = rest[k] || null;
}
```

`name`, `city` и `tier` в схеме **NOT NULL**. Стоило владельцу очистить любое из них в форме — Prisma отвергала весь update, и не сохранялись заодно все остальные поля. `any` глушил компилятор, который иначе показал бы это сразу: после замены на `Prisma.RestaurantUpdateInput` ошибка типов вылезла именно на этих трёх строках. Поля перечислены явно, обязательные меняются только на непустое значение.

### P1 — брифинг журнала верил модели на слово

[api/admin/magazine/brief/route.ts](../apps/web/src/app/api/admin/magazine/brief/route.ts) объявлял результат `generateJSON` как `Record<string, string>`, хотя функция возвращала `any`. Верни модель вложенный объект вместо строки — он ушёл бы в вёрстку как `[object Object]`. Добавлена фильтрация: в результат попадают только строки.

### P1 — `status as any` глушил единственную проверку статуса

### `any`

Разбор по видам: 43 — `catch (error: any)`, 53 — структурные (`Record` от Prisma, ответы внешних API, части запросов к моделям). Правились не заменой на `unknown`, а нормальными типами: `Prisma.CustomerWhereInput`, `Prisma.InputJsonValue`, `OrderStatus`, `z.infer` от существующих zod-схем, локальные интерфейсы под ответы Graph API и Gemini/OpenAI.

В [lib/safeError.ts](../apps/web/src/lib/safeError.ts) добавлены два помощника рядом с уже существовавшим `safeError`: `clientErrorMessage` (текст ошибки для показа в браузере — там ошибка своя, серверных внутренностей в ней нет) и `prismaErrorCode` (безопасное чтение `P2002` и подобных вместо `error.code` на `any`).

Правило `@typescript-eslint/no-explicit-any` в [eslint.config.mjs](../apps/web/eslint.config.mjs) переведено с `warn` обратно на **`error`** — послабление стояло с комментарием «systematic removal requires major refactor», этот рефакторинг сделан.

### Цвета

Заменены на токены 127 литералов + 29 `color: '#fff'` → `var(--text-inverse)`. Трёх значений в системе не было вовсе — добавлены в [tokens.json](../apps/web/design-system/tokens/tokens.json) и собраны штатным `npm run tokens:build`:

- `--brand-primary-deep` (`#047857` / `#065F46`) — тёмный конец брендовых градиентов;
- `--brand-primary-soft` (`#6EE7B7` / `#A7F3D0`) — светлый конец, логотип;
- `--surface-ink` (`#0F172A`) — тёмная подложка промо-блоков главной.

**Законные исключения, оставлены намеренно с комментарием в коде:**

| Где | Почему |
|---|---|
| `opengraph-image.tsx`, `twitter-image.tsx` | Satori/`ImageResponse` не резолвит CSS-переменные |
| `layout.tsx`, `m/[slug]/d/[code]` — `themeColor` | Уходит в манифест PWA и мета-тег системного браузера |
| `TelegramInit.tsx` — `setHeaderColor` | Нативный клиент Telegram, CSS там не существует |
| `lib/magazine/frame.ts`, `lib/magazine/qr.ts`, `magazine/dishes/qr/route.ts` | Генерация самодостаточного SVG/canvas для печати |
| `MicrogreensCanvas.tsx`, `Tamagotchi.tsx` | Рисование в canvas 2D |
| `InstagramFeed.tsx`, `TelegramLoginButton.tsx`, кнопка Telegram в `/magazine` | Фирменные цвета чужих брендов — не наша система |
| `components/magazine/blocks.tsx` | Печатная палитра FRESH WEEKLY (A5, единицы `pt`/`mm`) — отдельный бренд журнала |
| `var(--bg-primary, #0B0B14)` и подобные | Это и есть правильный паттерн: фолбэк **внутри** `var()` |

**Две регрессии, которые механическая замена внесла и которые пришлось откатывать вручную** — записаны, чтобы следующий раз не наступить:

1. `TelegramInit.setHeaderColor('var(--brand-primary)')` — Telegram не разворачивает `var()`, шапка осталась бы без цвета.
2. `AdminAnalytics` — матрица ABC-XYZ: `#10B981` и `#34D399` оба отображались в `--brand-primary`, и два соседних класса из девяти слились в один цвет. Переведено на категориальную палитру `--cat-*`, которая для этого и существует.

Отдельно: `/api/inventory/analytics` отдавал витрине **готовый hex** (`healthColor`), а витрина клеила к нему `15` для полупрозрачного фона (`${healthColor}15`). Палитра склада жила мимо дизайн-системы и не переключалась вместе с темой. Теперь API отдаёт **уровень** (`healthLevel: ok | info | warning | critical`), цвет выбирает витрина по токенам, фон — через `color-mix`.

### `eslint-disable`

Из 12 подавлений **5 были мертвы**: они глушили `@next/next/no-img-element`, а это правило уже выключено глобально в конфиге. Удалены.

Ещё одно (`no-explicit-any` в `AiChatWidget` для Web Speech API) тоже оказалось мёртвым — типы объявлены в `types/telegram.d.ts`. Удалено.

`no-require-imports` в `rateLimit.ts` (необязательная зависимость `ioredis`) вынесено из кода в конфиг, рядом с таким же исключением для `next.config.ts`.

Осталось **4**, все — `react-hooks/exhaustive-deps`, все теперь именуют конкретное правило и объясняют причину. Три из них были написаны как голое `// eslint-disable-line` без правила и без объяснения. Причина везде одна: добавление зависимости даёт бесконечный цикл, потому что функция пересоздаётся каждый рендер и сама трогает то, на что подписана.

Заодно в конфиг добавлены штатные опции `no-unused-vars` (`ignoreRestSiblings`, `^_`): без них правило ругалось на `const { secret, ...rest } = obj` — обычный способ убрать поле из ответа API — и приучало глушить себя целиком.

Путь `raise_alert` из незакоммиченного `stepan_bot/main.py` статически сходится с контрактом ([owner_alerts.py:39](../apps/tgas/shared/owner_alerts.py#L39)), но живьём его подтвердит только прод или база с актуальной схемой.

### Моя собственная регрессия, найденная и откаченная

При типизации [products/route.ts](../apps/web/src/app/api/products/route.ts) я заменил `specs: specs || null` на `specs ?? Prisma.JsonNull`. Это **не** эквивалент: `JsonNull` пишет в колонку JSON-литерал `null`, а `DbNull` — SQL NULL. После такой замены запрос `WHERE specs IS NULL` перестал бы находить товары. ### E2E доведены до зелёного: 34 из 34

После правки сценариев осталась плавающая часть — тесты то проходили, то нет. Причина оказалась общая и не про витрину: **ввод и клики попадали в ещё не гидратированную страницу**. `fill` писал в «мёртвую» разметку, React затем возвращал управляемому полю значение из состояния (пустую строку), а клик уходил в неподключённый роутер Next — элемент заменялся прямо под курсором (`element was detached from the DOM`). Успеет гидратация до действия или нет, зависело от загрузки машины.

Установлено пробой: `fill` сразу после `domcontentloaded` даёт пустое поле все 4.4 секунды наблюдения; тот же `fill` после появления карточек товара — устойчивое значение. Теперь сценарии ждут клиентской отрисовки товаров как признака завершённой гидратации.

Вторая причина: на мобильном профиле первой в DOM идёт ссылка десктопной шапки — скрытая и некликабельная. Берётся первая **видимая**, иначе сценарий зелёный на десктопе и красный на телефоне.

Итог: **34 из 34** на обоих профилях (chromium + Pixel 5), 41 секунда, два прогона подряд с одинаковым результатом.

## Итог

Красным было одно: сверки ИИ-офиса не запускались вовсе. Закрыто.

Остальное — не поломки, а долг, который копился и уже начал давать поведенческие дефекты: `any` прятал запись `null` в NOT NULL и разрешал сырой текст ошибки Prisma в ответе API; молчащие `catch` прятали отказы; цвета мимо токенов не переключались вместе с темой; расход на эмбеддинги шёл мимо учёта. Всё перечисленное устранено, ворота зелёные, правило `no-explicit-any` возвращено в ранг ошибки, чтобы долг не набежал заново.
