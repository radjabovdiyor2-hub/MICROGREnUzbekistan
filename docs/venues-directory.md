# Справочник заведений Самаркандской области

Как наполнить раздел «Клиенты» и карту всеми ресторанами, кафе, тойхонами,
фитнес-клубами и прочими заведениями области — и что при этом нельзя ломать.

## Что где лежит

| Слой | Файл | Роль |
|---|---|---|
| Таксономия | [companyTypes.ts](../apps/web/src/lib/customers/companyTypes.ts) | 19 типов заведений, 3 группы, 8 цветовых корзин, аудитория |
| Районы | [districts.ts](../apps/web/src/lib/customers/districts.ts) | 2 тумана города + 14 туманов области |
| Зона обслуживания | [addressKey.ts](../apps/web/src/lib/customers/addressKey.ts) | написания городов и райцентров → slug зоны |
| Сбор | [lead_gen.py](../apps/tgas/shared/lead_gen.py) | `VENUE_QUERIES`, `SAMARKAND_PLACES`, три провайдера, дедуп |
| CLI сбора | [collect_restaurants.py](../apps/tgas/scripts/collect_restaurants.py) | обход категорий × населённых пунктов |
| Загрузка выгрузки | [seed-venues.ts](../packages/database/prisma/seed-venues.ts) | JSON → `customers`, идемпотентно |
| Геокодер | [geo.py](../apps/tgas/shared/geo.py) | координаты и район по адресу |
| Карта | [mapQuery.ts](../apps/web/src/lib/customers/mapQuery.ts) | фильтры, GeoJSON, разрез по районам |

Таксономия и список районов существуют **в двух экземплярах** — в TypeScript и
в Python. Дублирование намеренное: прямых импортов между модулями нет
(см. [CLAUDE.md](../CLAUDE.md)). Расхождение ловят
`apps/web/src/lib/customers/districts.test.ts` и
`apps/tgas/tests/test_lead_gen_venues.py` — не правьте один список, не тронув
второй.

Источники, честно проставленные в `customers.source`:

  Самарканда 3475 (рестораны), 108609 (банкетные залы), 109347 (тренажёрные залы);

**Телефонов в этих карточках нет.** Все три справочника их маскируют
(`+998 (91) 528-XX-XX`), а дописать недостающие цифры значит выдумать номер.
Телефоны доберёт сбор через 2ГИС.

**Координат тоже нет** — все 211 лежат в лотке «Без координат» на карте, пока
не отработает геокодер (шаг 5 ниже). Список при этом полон и работает сразу.

Три женских фитнес-клуба (`ELITE`, `LADY-GYM`, `Elite Fitness Centre`)
помечены `audience = female` по собственной подписи справочника, с
`audience_source = 'guess'`: это не наша проверка, и продавец вправе уточнить.

## Наполнение до полного справочника

### 1. Ключ провайдера

Нужен хотя бы один в `apps/tgas/.env`:

```
DGIS_API_KEY=...            # лучшее покрытие в Узбекистане
YANDEX_MAPS_API_KEY=...     # хорошая альтернатива
GOOGLE_PLACES_API_KEY=...   # потолок 60 карточек на запрос
```

Провайдер без ключа молча пропускается и не мешает остальным. **Без единого
ключа собрать нечего** — выдумывать названия и адреса заведений нельзя:
фальшивая карточка в CRM хуже пустой карты, по ней поедут.

### 2. Сбор

```bash
cd apps/tgas
# Весь справочник области: 19 категорий × 15 населённых пунктов × 3 провайдера
python -m scripts.collect_restaurants --source api --all-categories --all-places

# Точечно
python -m scripts.collect_restaurants --source api \
    --category toyxona --category fitness --place Urgut

# Собрать в файл, не трогая базу, — посмотреть выгрузку глазами
python -m scripts.collect_restaurants --source api --all-categories --all-places \
    --out ../../content/venues-samarkand.json
```

Полный обход — это сотни запросов. Он рассчитан на разовый прогон; в рабочем
режиме `collect_leads_nightly` в `marketing_bot` берёт **по одной категории за
ночь** (ротация по дню года) и проходит весь справочник за 19 ночей, не выжигая
суточную квоту провайдера.

### 3. Из файла в базу

```bash
cd packages/database && npm run db:seed:venues
```

Читает `content/venues-samarkand.json`. Идемпотентно по `(source, source_ref)`:
повторный прогон обновляет, а не плодит.

### 4. Ручной список от полевой команды

```bash
python -m scripts.collect_restaurants --source manual --file venues.csv
```

Колонки CSV (обязательна одна — `company_name`):

```
company_name,phone,email,address,city,district,company_type,audience,
latitude,longitude,review_score,review_summary,source_ref
```

`company_type` — slug из `COMPANY_TYPES` (`toyxona`, `fitness`, `cafe`…),
`district` — slug из `DISTRICTS` (`urgut`, `kattaqorgon`…), `audience` —
`female` / `male` / `mixed`. Заполненная в CSV аудитория помечается как
**ручная** и автоматикой больше не перезаписывается.

### 5. Координаты для тех, кто приехал без них

```bash
cd apps/tgas
python -c "import asyncio; from shared.geo import geocode_pass; asyncio.run(geocode_pass(batch=200))"
```

Или кнопкой «Геокодировать» в лотке «Без координат» на карте. Геокодер
заодно проставляет район по адресу.

## Пол зала: женский и мужской

Ни 2ГИС, ни Google, ни Яндекс этот признак не проставляют. Поэтому:

1. `guess_audience()` угадывает по названию — `Ayollar`, `Женский`, `Women`,
   `Lady` → женский; `Erkaklar`, `Мужской`, `Mens` → мужской. Результат
   помечается `audience_source='guess'`.
2. Всё остальное приезжает как **«не выяснено»** (`NULL`), а не «смешанный»:
   разница рабочая — невыясненное продавец обязан спросить при первом звонке,
   смешанное уже спросил.
3. Продавец правит поле в карточке клиента. Сохранённое руками помечается
   `audience_source='manual'` и **автоматикой не перезаписывается никогда**.

Фильтр «Не выяснено» на карте и в списке — это рабочая очередь: кому ещё надо
позвонить и уточнить.

## Инварианты, которые нельзя нарушать

- `geo_source='manual'` — координату, поставленную человеком, не перезаписывает
  ни геокодер, ни сборщик, ни сидер.
- `audience_source='manual'` — то же для пола зала.
- `status` монотонен: повторный сбор не разжалует активного клиента обратно в
  лид.
- Точность «город» → пин НЕ ставим, заведение уходит в лоток. Ложная точка в
  центре Самарканда хуже отсутствующей.
- Slug района канонический. `customers.district` хранит `urgut`, а не «Ургут»:
  отображаемые имена приклеиваются на границе с интерфейсом.
- В `_DISTRICTS` геокодера **нет и не должно быть слова «samarqand»**: оно
  стоит в каждом городском адресе, и весь Самарканд разом уехал бы в сельский
  туман. Самаркандский район распознаётся по названию своего центра — Гулобод.

## Что видно в интерфейсе

`/admin?tab=customers`:

- **Список** — селекты «Тип заведения» и «Аудитория» рядом с поиском; тип,
  район и пол зала видны в первой колонке; правятся в карточке клиента.
- **Карта** — лента чипов по типам (тремя группами), лента аудитории у
  фитнеса, спорта и тойхон; режим раскраски «По типу заведения» с легендой из
  восьми корзин; разрез по районам показывает состав: «40 тойхон · 12 кафе».

Цвет на карте отвечает за **корзину**, а не за категорию: различимых цветов
восемь, а категорий девятнадцать. Точный тип — в фильтре и в карточке точки.
