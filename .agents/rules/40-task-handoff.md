# Шаблон передачи задачи быстрой модели

Активация: **Manual** (@-упоминание). Не Always On — это инструкция для человека, а не для каждого хода.

Gemini 3.6 Flash хорошо исполняет и плохо декомпозирует. Кросс-модульная задача, поставленная
одной фразой («почини пульт ИИ»), у него разваливается: цепочка `apps/web` → HTTP → `apps/tgas`
не выводится за один проход. Поэтому разделение труда:

| Этап | Кто | Чем |
|------|-----|-----|
| Спека, план, декомпозиция | Claude или Gemini 3.1 Pro | `/speckit-specify` → `/speckit-plan` → `/speckit-tasks` |
| Реализация | Gemini 3.6 Flash | `/speckit-implement` по готовому `tasks.md` |
| Верификация | Flash | `npm run lint`, `npm run build`, `py_compile` |

## Критерий атомарности задачи

Задача в `tasks.md` годится для Flash, если выполняются все четыре условия:

1. Названы **точные пути** всех файлов, которые надо открыть и изменить. Ни одного «найди, где…».
2. Правка укладывается в **один модуль**. Если нужны и `apps/web`, и `apps/tgas` — это две задачи,
   связанные порядком, а не одна.
3. Есть **проверяемый критерий готовности**: конкретная команда и её ожидаемый результат.
4. Понятно, **что не трогать** — соседние файлы, генерируемые артефакты, чужие модули.

Не выполняется хотя бы одно — дробить дальше. Если Flash буксует на `/speckit-implement`,
причина почти всегда здесь, а не в модели.

## Шаблон промпта (когда идёшь мимо Spec Kit)

```
Задача одним предложением: <что должно измениться и где>.

Файлы (других не открывать):
- <точный/путь/файл.ts>  — <что именно тут поменять>
- <точный/путь/файл.py>  — <что именно тут поменять>

Контекст маршрута: <либо ссылка на раздел «Маршруты» в AGENTS.md, либо цепочка целиком>

Не делать: не рефакторить соседний код, не переименовывать, не добавлять зависимости,
не коммитить, не трогать <перечислить>.

Готово когда: <команда> выводит <ожидаемый результат>.

Отчёт: что изменено (файл:строка) → чем проверено (команда и её вывод) → что осталось
непроверенным.
```

## Частые срывы и что с ними делать

- **Выдумал путь или имя функции.** Значит, в промпте не было точного пути. Добавить.
- **Отчитался «готово» без запуска проверки.** Требование верификации должно стоять
  отдельной строкой «Готово когда», а не подразумеваться.
- **Правка одной стороны HTTP-границы.** Задача была не атомарной: в ней сидели два модуля.
  Разбить на пару связанных задач с явным порядком.
- **Расползание правки на соседние файлы.** Не был указан раздел «Не делать».
