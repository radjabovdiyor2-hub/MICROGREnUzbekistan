# Microgreen Design System — правила фронтенда

Единая система: **токены → компоненты → шаблоны**. Один источник токенов,
проверяемые компоненты (Storybook), мост в Figma. Эти правила — обязательны для
нового кода и служат ориентиром при рефакторинге старого.

> TL;DR: **не хардкодь hex/px в компонентах** — только токены (CSS-переменная или
> Tailwind-утилита). Новый компонент = файл в `src/components/ui/` + `*.stories.tsx`
> со всеми состояниями + светлая/тёмная тема + a11y.

---

## Три уровня

| Уровень | Что | Где |
|---|---|---|
| **1. Токены** | цвета, типографика, отступы, радиусы, тени, z-index; свет+тьма | `design-system/tokens/tokens.json` → сборка в `build/*` |
| **2. Компоненты** | Button, Card, Badge, Input, Modal, Toast, Progress, Skeleton — все состояния | `src/components/ui/*` (+ `*.stories.tsx`) |
| **3. Шаблоны** | реальные блоки/экраны: product-grid, footer, section, hero | `src/app/styles/templates.css` + `Templates/*` сторис |

Карта файлов:

```
design-system/
  tokens/tokens.json        ← ЕДИНЫЙ ИСТОЧНИК токенов (W3C DTCG / Tokens Studio)
  build-tokens.mjs          ← генератор (zero-dep; можно заменить на Style Dictionary)
  build/                    ← СГЕНЕРИРОВАНО, но коммитится:
    tokens.css              ←   рантайм CSS-переменные (:root / [data-theme])
    theme.css               ←   Tailwind v4 @theme (утилиты из токенов)
    tokens.ts               ←   типизированный экспорт для JS-логики
  README.md · FIGMA.md      ← эти правила + playbook Figma
src/app/globals.css         ← точка входа: @layer + все @import + легаси-классы
src/app/styles/
  components.css            ← тир-2: новые/консолидированные классы компонентов
  templates.css            ← тир-3: блоки/лейауты
src/components/ui/*         ← тир-2: React-примитивы + сторис
.storybook/*               ← каталог состояний
```

## Токены — как устроен пайплайн

1. Правишь **`tokens/tokens.json`** (единственный источник правды).
2. Гонишь генератор:
   ```bash
   npm run tokens:build          # → build/tokens.css, build/theme.css, build/tokens.ts
   ```
3. Коммитишь и `tokens.json`, и `build/*` (приложение импортит `build/*` напрямую,
   поэтому они должны быть в репозитории; `.gitignore` для них снят намеренно).

`globals.css` подключает всё в самом верху (порядок важен — все `@import` идут
подряд, сразу после объявления слоёв):

```css
@layer theme, base, components, utilities;
@import url('…fonts…');
@import "../../design-system/build/tokens.css";      /* рантайм-переменные */
@import "tailwindcss/theme.css" layer(theme);        /* Tailwind без Preflight */
@import "tailwindcss/utilities.css" layer(utilities);
@import "../../design-system/build/theme.css";        /* токены → @theme */
@import "./styles/components.css";                    /* тир-2 */
@import "./styles/templates.css";                     /* тир-3 */
```

**Preflight (сброс Tailwind) намеренно НЕ подключён** — у проекта свой reset и
2000+ строк легаси-классов; Preflight бы их сломал. Утилиты лежат в `@layer
utilities` (ниже нелейерных легаси-классов), поэтому компоненты сохраняют вид, а
утилиты закрывают пробелы и работают на новой разметке.

## Правила

### Токены
- **Никакого хардкода** hex/rgb/px в компонентах. Только `var(--token)` или
  Tailwind-утилита. Исключение — «на цвете» (белый текст на брендовой кнопке
  выражается токеном `--text-inverse`, см. кейс ниже).
- Новый токен → добавь в `tokens.json`, запусти `tokens:build`, закоммить `build/*`.
  Не редактируй `build/*` руками (перезатрётся).
- Имя переменной = путь в JSON без корня: `light.brand.primary-hover` → `--brand-primary-hover`.
- Тема переключается атрибутом `[data-theme="dark"]` на `<html>` (см. `ThemeProvider`).

### Компоненты (тир-2)
- Живут в `src/components/ui/`, тонкие типизированные обёртки над классами/токенами.
- **Обязателен `*.stories.tsx`** с каталогом состояний: варианты, размеры,
  `default / hover / disabled / loading`, ошибка, светлая **и** тёмная тема, адаптив.
- Доступность: видимый `:focus-visible` (есть глобально), тач-цели ≥ 44px
  (`btn-icon`, `--bottom-nav`), уважение `prefers-reduced-motion`.
- Новые классы компонентов → `src/app/styles/components.css` (token-only), не в
  инлайн-стили и не новыми хексами.

### Шаблоны (тир-3)
- Композиции реальных блоков/экранов → `src/app/styles/templates.css` +
  `Templates/*` сторис как эталон «правильной композиции».

### Tailwind-утилиты (что доступно из токенов)
- **Цвета** (theme-aware): `bg-brand-primary`, `text-text-secondary`,
  `border-border`, `bg-success`, `text-error`, `bg-scrim`, … — переключаются с темой.
- **Радиусы**: `rounded-sm|md|lg|xl|2xl|full`.
- **Типографика**: `text-xs … text-4xl`, `font-body`, `font-display`.
- **Отступы**: стандартные `p-4`, `gap-6`, … — наша шкала `--space-*` совпадает с
  дефолтной шкалой Tailwind, поэтому отдельного маппинга нет.
- **Тени/z-index/переходы** в `@theme` НЕ вынесены (тени зависят от темы и имя
  ключа Tailwind совпадает с именем рантайм-переменной). Используй класс `.card`
  или произвольное значение: `shadow-[var(--shadow-card)]`.

## Кейс из эталонного экрана (ProductCard)

Reference-компонент — [`src/components/shop/ProductCard.tsx`](../src/components/shop/ProductCard.tsx).
При переводе на систему нашли и починили системные косяки:

- `#F59E0B` у звезды рейтинга → `var(--brand-accent)` (единый токен рейтинга).
- `rgba(0,0,0,0.3)` у кнопки «избранное» → новый токен `var(--scrim)`.
- `color: '#fff'` в степпере/кнопке корзины → `var(--text-inverse)`. Это **не
  косметика**: в тёмной теме `--brand-primary` — светло-мятный `#34D399`, и белый
  текст на нём проваливал контраст. `--text-inverse` в тёмной теме тёмный →
  контраст исправлен (та же логика, что в `.btn-primary`).

**Известный техдолг (чистить инкрементально при масштабировании, тир-3):**
в `globals.css` `.product-card:hover` объявлен несколько раз (−3/−4/−6px);
«канонический» правит финальным `!important`. Ранние дубли мёртвые — убирать по
одному блоку с визуальной проверкой, не массово.

## Масштабирование (продолжается инкрементально)

Система, эталон и правила готовы. Дальше — переводить остальные экраны по одному,
сверяясь с этими правилами (порядок из ролика: сначала эталон → потом масштаб).

Бэклог на момент внедрения: **~240 захардкоженных hex в 40 файлах** (замер
`rg '#[0-9A-Fa-f]{6}' src/components`). Крупнейшее — админка
(`AdminGrowing` ~38, `AdminPOS` ~21, `NutritionistPanel` ~13, `AdminStats` ~12).
Новые примитивы `components/ui/*` — уже чистые (0 хардкода).

Важно: **не всё это баги.** Часть хексов легитимна — цвета canvas/three.js,
палитры графиков, намеренные брендовые градиенты, цветокодирование категорий.
Правило: переводи на токены **UI-хром** (фоны/текст/бордеры/тени поверхностей),
а осмысленные данные/бренд-цвета оставляй (или заводи под них именованные токены).
Мигрируй по одному компоненту, каждый — с визуальной сверкой светлой/тёмной темы.

## Команды

```bash
npm run tokens:build     # пересобрать токены после правки tokens.json
npm run storybook        # каталог компонентов (localhost:6006) — проверка состояний/тем
npm run build-storybook  # статическая сборка каталога
npm run build            # прод-сборка приложения (интеграционная проверка)
```

## Как проверять
1. `npm run storybook` → каждый примитив во всех состояниях; тумблер темы в тулбаре;
   свет/тьма/загрузка/ошибка/адаптив.
2. `npm run build` → зелёный (CSS-импорты резолвятся, `@theme` собирается).
3. После правки токенов — `tokens:build`, затем визуально сверить, что рендер не поехал.

Figma и мост токенов — см. [FIGMA.md](./FIGMA.md).
