# Приложение для полевых сотрудников (Android)

Оболочка вокруг той же админки. Отличие ровно одно и ради него всё
делалось: **координаты даёт система, а не вкладка браузера** — телефон
пишет маршрут с погашенным экраном и в кармане.

Всё остальное — смена, «мой день», «я на точке», фото, карта, касса —
это тот же сайт, открытый внутри приложения. Второго интерфейса нет
намеренно: две копии одного экрана расходятся на первой правке.

## Что внутри

| Файл | Зачем |
|---|---|
| `capacitor.config.json` | Адрес админки, имя приложения, страница «нет связи» |
| `www/offline.html` | Честное «связи нет, маршрут копится» вместо ошибки браузера |
| `.github/workflows/android.yml` | Сборка APK: Android SDK живёт только там |

Родного проекта (`android/`) в репозитории нет: его генерирует
`npx cap add android` — одинаково из конфига и списка плагинов.

## Как собрать APK

Вкладка **Actions → Android APK → Run workflow**. Через 5–7 минут файл
лежит в артефактах сборки. Тег `apk-v1.4` вместо кнопки — файл ещё и
приложится к релизу.

Локально сборка не нужна и почти невозможна: требуются JDK 21 и Android
SDK (~5 ГБ). Если всё же понадобится:

```bash
cd mobile && npm ci && npx cap add android && npx cap sync android
cd android && ./gradlew assembleDebug
```

### Ключ подписи — сделать ОДИН раз

Android не ставит обновление поверх приложения, подписанного другим
ключом. У отладочной сборки ключ создаётся заново на каждом прогоне CI —
то есть каждая сборка «чужая», и обновление требует удалить приложение
вместе с ключом устройства.

```bash
keytool -genkeypair -v -keystore mg.keystore -alias microgreen \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 mg.keystore > mg.keystore.b64
```

Дальше в настройках репозитория (Settings → Secrets and variables →
Actions) завести четыре секрета:

- `ANDROID_KEYSTORE_BASE64` — содержимое `mg.keystore.b64`;
- `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_PASSWORD` — пароли из `keytool`;
- `ANDROID_KEY_ALIAS` — `microgreen`.

**Файл `mg.keystore` хранить вне репозитория и не терять.** Потеряется —
обновления перестанут ставиться поверх, и всем придётся переустанавливать
приложение заново.

## Как поставить сотруднику

1. Передать файл `.apk` (проще всего — переслать в Telegram).
2. Открыть его на телефоне. Android спросит разрешение ставить
   приложения из этого источника — разрешить.
3. Открыть приложение, войти по своему **PIN** — тому же, что в админке.
4. Нажать **«Начал смену»**. Телефон спросит доступ к геопозиции — выбрать
   **«При использовании приложения»**; этого достаточно, потому что запись
   стартует, когда приложение открыто.
5. Появится постоянное уведомление **«Смена идёт»** — по нему видно, что
   маршрут пишется. Убрать его нельзя, и это правильно: человек обязан
   видеть, что его пишут.

### Пять минут в фоне: `useLegacyBridge`

`capacitor.config.json` обязан держать `android.useLegacyBridge: true` — без
этой строки **служба замолкает через пять минут после сворачивания
приложения**. Это не догадка и не «оптимизация батареи»: так написано в
README самого плагина (`@capacitor-community/background-geolocation`,
раздел Android, ссылка на issue #89).

Симптом ровно такой, каким его видит владелец: несколько точек, пока экран
горел, потом тишина — и на карте прямая линия через полгорода между первой
и последней точкой. Отличить это от «человек не включил запись» по карте
нельзя; отличается оно только по частоте точек в строке «Сейчас в поле».

Сюда же — ещё одна оговорка из того же README: после пяти минут в фоне
Android придерживает HTTP-запросы, начатые из вкладки. У нас это не теряет
крошки — очередь лежит в `localStorage` и уходит, когда приложение
возвращается на экран, — но точки приезжают с задержкой, и «молчит N минут»
в этот момент говорит правду про связь, а не про человека.

### Уведомление на Android 13 и новее

Постоянное уведомление «Смена идёт» — не формальность: человек обязан
видеть, что его пишут. Но модуль геопозиции просит только доступ к
координатам, право показывать уведомления он не запрашивает вовсе, и на
Android 13+ без этого права уведомление НЕ ПОКАЗЫВАЕТСЯ — служба работает
молча.

Поэтому в сборке есть `@capacitor/local-notifications`: он нужен ровно ради
одного вызова — спросить это право перед запуском службы
(`apps/web/src/lib/native/geo.ts`, `askForNotice`). Уведомлений приложение
не шлёт.

Отказ в этом праве **не останавливает запись**: это разные разрешения, и
гасить трек из-за не того отказа было бы наказанием не за то. Но тогда
пропадает и проверка «видно ли уведомление» — а она самая быстрая, чтобы
понять, работает ли служба.

Выдать вручную: **Настройки → Приложения → Microgreen → Уведомления →
Разрешить**.

### Обязательный шаг на Xiaomi, Huawei, Oppo, Vivo

У этих производителей своя «оптимизация батареи» поверх Android, и она
гасит фоновые службы молча. Маршрут будет рваться так же, как без
приложения, но уже без объяснения.

- **Настройки → Приложения → Microgreen → Батарея → Без ограничений**
  (или «Разрешить фоновую активность»);
- **Автозапуск** — включить;
- на Xiaomi дополнительно: **Безопасность → Батарея → Экономия
  энергии → Microgreen → Нет ограничений**.

Названия пунктов у каждой прошивки свои — искать по словам «батарея»,
«автозапуск», «фоновая работа».

## Что это приложение НЕ делает

- **Не пишет вне смены.** Служба стартует по кнопке «Начал смену» и
  гаснет по «Закончил смену». Закрытая смена — записи нет.
- **Не работает после того, как приложение выгрузили из памяти.** Android
  может убить процесс: маршрут за это время не пишется, а накопленное
  уходит при следующем запуске. Трансляция в Telegram в этом смысле
  надёжнее — она живёт в самом Telegram.
- **Не заменяет вход.** Ключ устройства выдаётся после входа по PIN и
  отзывается владельцем в админке (вкладка «Сотрудники»).

## Ключ устройства

Приложение получает свой ключ (`mgd_…`) один раз после входа и шлёт им
трек — даже когда сессия давно истекла. Ключ открывает ровно две двери:
свой трек и свою смену.

Владелец видит все телефоны в админке и гасит любой одной кнопкой:
уволился, потерял телефон, сменил аппарат. После отзыва запись с этого
телефона прекращается сразу; человек может войти заново и получить новый.
