# GEMINI.md — Microgreen Uzbekistan

Ты работаешь на живом продакшн-репозитории. Твои правки уезжают в прод.

Этот файл — только маршрутизатор. Содержание разнесено по трём документам, чтобы каждый
укладывался в лимит правил (12 000 символов) и не дублировал соседей:

| Что нужно | Где лежит |
|-----------|-----------|
| **Что это за проект** — модули, сквозные маршруты, порты, запреты, команды | `AGENTS.md` (корень) |
| **Как работать** — разведка, правки, верификация, git-безопасность, условия остановки | `.agents/rules/00-protocol.md` |
| **Что можно утверждать** — дисциплина рассуждений, §1–§10 + FINAL GATE | `.agents/AGENTS.md` |
| **Полный свод правил проекта** | `.specify/memory/constitution.md` |

Antigravity подхватывает `AGENTS.md` и `.agents/rules/**` сам. Gemini CLI видит только этот
файл — если ты Gemini CLI, прочитай `AGENTS.md` и `.agents/rules/00-protocol.md` перед первым
содержательным ответом.

При конфликте: конституция > протокол работы > дисциплина рассуждений.

## Что важно помнить всегда

1. **Не выдумывай.** Не читал в этой сессии — не знаешь. Пути файлов, имена функций, роуты,
   env-переменные и флаги CLI проверяй, а не вспоминай.
2. **Не заявляй успех без проверки.** «Готово» допустимо только после того, как ты запустил
   `npm run lint` / `npm run build` / `py_compile` и увидел результат. Прочитать свой диff —
   это не проверка.
3. **Ошибки показывай дословно.** Провал, пересказанный как успех, — сорванный ход.
4. **Не расширяй задачу.** Чинишь то, о чём просили. Рефакторинг — отдельная работа.
5. **Никаких git side effects** без явной просьбы в этом же ходе.
6. **Секреты не печатать и не коммитить.** Увидел ключ в коде — остановись и доложи.
7. **Три попытки.** Одна и та же ошибка пережила три захода — стоп, доклад с гипотезами.

## Кросс-модульные задачи

Если правка задевает и `apps/web`, и `apps/tgas` (например, пульт ИИ в админке) — не держи
цепочку в голове. Сначала посмотри раздел «Маршруты» в `AGENTS.md`: скорее всего она уже
описана с точными файлами и портами. Если нет — прогони `/speckit-specify` → `/speckit-plan`
→ `/speckit-tasks` и только потом пиши код.
