## Раздел 5. AI — инфраструктура модели (12–17)

**Общий принцип:** собственная модель НЕ обучается. Используются готовые LLM
(Google Gemini 2.5 Flash/Pro, OpenAI GPT-4o/4o-mini) через системный prompt-engineering,
динамическую подстановку контекста (dynamic context injection) и RAG (pgvector). Поэтому
метрики обучения (accuracy/F1, overfitting, SHAP) неприменимы — качество измеряется иначе
(QA-бот, CSAT, учёт стоимости, контроль «галлюцinаций»).

### 12. Архитектура модели
- **Framework / библиотеки:** обучающих фреймворков (TensorFlow/PyTorch/Scikit-learn) НЕТ —
  модель не тренируется. Используются: hosted LLM API (Gemini REST, OpenAI SDK), `pgvector`
  (эмбеддинги/RAG), оркестрация — aiogram 3, FastAPI, SQLAlchemy 2.0, aiohttp; веб — Next.js 16.
- **Обучение и инференс (GPU/TPU/cloud/on-prem):** обучения нет; инференс — облачные API
  провайдеров (Google/OpenAI), GPU на нашей стороне не нужен. On-prem (VPS + Docker) — только
  оркестрация ботов и данные.
- **AI-pipeline (training/deployment/monitoring) автоматизирован:** обучения нет; генерация и
  публикация автоматизированы (scheduler + event-bus/bot-bus); мониторинг — QA-бот (проверка
  ответов), учёт токенов/стоимости (`ai_usage` + ежедневный отчёт), heartbeat ботов, CSAT.

### 13. Данные (Data)
- **Объём / качество / баланс:** обучаемого датасета нет. «Данные» = оперативная БД: каталог
  товаров, B2B-база ресторанов, история диалогов (`interactions`), FAQ-архив; для RAG — векторные
  эмбеддинги в pgvector. Качество поддерживается нормализацией и дедупликацией.
- **Легальность / лицензии источников:** собственные бизнес-данные компании + публичные источники
  (RSS-новости, тренды). B2B-лиды — 2ГИС Catalog API (по ToS, лицензионный ключ). Скрейпинг карт
  и Telegram намеренно НЕ реализован (против ToS).
- **Версионирование / очистка:** дедупликация лидов (`source_ref` → телефон → название),
  нормализация; версионирование схемы БД — через `init.sql` / `schema.prisma` (git).

### 14. Результаты модели
- **Метрики (accuracy/precision/recall/F1):** неприменимы (модель не обучается). Качество ответов
  оценивается через: QA-бот (автопроверка корректности), CSAT-опросы (n8n-вебхуки), feedback loop
  администратора (👍/👎 в групповых чатах).
- **Overfitting / underfitting:** неприменимо (нет обучения). Риск «галлюцинаций» LLM снижается
  системными промптами (приоритет над вводом), RAG и строгой контент-политикой («не выдумывать
  факты/цифры»).
- **Explainability (SHAP/LIME):** для LLM неприменимо; прозрачность обеспечивается логированием
  промптов/ответов и явными источниками RAG.

### 15. Безопасность
- **Adversarial / poisoning:** poisoning-канала нет (на пользовательском вводе не обучаемся).
  Prompt-injection митигируется: системный промпт приоритетнее ввода, строгая тематическая
  контент-политика, ограниченная предметная область.
- **Приватность модели и данных:** PII не передаётся в промпты без необходимости; секреты — в env
  (не в репозитории); трафик — TLS; данные — на локальных серверах (Закон РУз «О перс. данных»).

### 16. Мониторинг и производительность
- **Drift detection / real-time monitoring:** дрейфа модели нет (не обучается). Мониторинг —
  учёт токенов и стоимости (`ai_usage`, ежедневный отчёт + бюджет-алерт), heartbeat/ошибки ботов
  (`/health/bots`), логи с ротацией.
- **Latency / throughput:** определяется провайдером LLM; фиксируется по каждому вызову
  (`UsageStats.duration_ms`). Боты асинхронные (aiogram/aiohttp) — параллельная обработка запросов.

### 17. Интеллектуальная собственность
- **Патент / open-source:** не патентуем. LLM используются по API-условиям провайдеров. Собственная
  IP — оркестрация (13 сервисов-ботов, самописные event-bus + bot-bus, RAG-пайплайн, контент-движок,
  индивидуализация журнала FRESH WEEKLY).
- **License compliance зависимостей:** зависимости — стандартный OSS с разрешительными лицензиями
  (aiogram/FastAPI/SQLAlchemy/Next.js — MIT, Prisma — Apache-2.0 и т.п.). Секрет-скан — gitleaks.
